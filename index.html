案例 A持续测试平台：从无人值守流水线到共享测试服务

背景
版本节奏加快、回归范围扩大，测试的准备、执行与取证高度依赖人工，人力消耗在环节衔接处而非判断上。
约束
设备与车辆资源有限且存在争用；环境状态复杂、复位困难；质量证据必须完整，不能为速度牺牲取证。
诊断
瓶颈不在单点执行速度，而在「触发—准备—执行—回传」的链路断裂：每个环节都能做，但串不起来。
干预
主导打通七步流水线（见图 3-1），把环境复位与资源调度做成一等环节；随后沿自动化成熟度路径推进服务化，让需求方可以自助触发（见图 3-2）。

图 3-1 ｜ 持续测试流水线七步链路

  1. 01版本触发
  2. 02制品获取
  3. 03环境复位
  4. 04软件升级
  5. 05资源调度
  6. 06执行取证
  7. 07结果回传

文字等价：按序为 版本触发 → 制品获取 → 环境复位 → 软件升级 → 资源调度 → 执行取证 → 结果回传；环境复位与资源调度前置保障无人值守成立。

图 3-2 ｜ 自动化成熟度演进路径

  1. L1无人值守单任务可自动执行
  2. L2并行资源多任务并发调度
  3. L3自助触发需求方自助发起
  4. L4场景编排任务可组合复用
  5. L5共享测试服务跨项目直接复用

文字等价：无人值守 → 并行资源 → 自助触发 → 场景编排 → 共享测试服务；每一级都以上一级的稳定运行为前提。

结果
版本级回归人力降至 ** 人时/版本，无人值守运行成为常态，取证材料随执行自动归集。
复盘
平台的价值不以「能跑」衡量，而以「他人能否在没有我的情况下自助使用」衡量。
主导角色
个人主导 七步流水线的早期建设；核心参与 平台核心能力与规模化运营为团队协作成果，非个人独立产出。

案例 B质量治理回路：让提效有靶心

背景
效率改进缺少统一方向，质量判断依赖个人经验，改进动作难以复盘与传承。
约束
质量数据分散在多处、口径不一；指标一旦上线，还可能被应付性达标。
诊断
先把「质量好不好」翻译成可计算、可复评的指标——漏测率 = 外部反馈故障分 ÷ 内部发现故障分；指标方向明确后，漏出分类才能反推测试盲区。
干预
建立「指标 → 漏出分类 → 根因 → 改进 → 复评」的闭环（见图 3-3），配套常见原因到改进动作的映射（见表 3-1）；针对数据反复拉取、结论难复用的问题，引入工作流自动化做数据同步与结构化治理。

图 3-3 ｜ 质量治理闭环

  1. 01指标
  2. 02漏出分类
  3. 03根因
  4. 04改进
  5. 05复评

⟲ 复评结果回流至「指标」，循环运转

文字等价：指标 → 漏出分类 → 根因 → 改进 → 复评，复评结果回流指标定义，形成闭环。

表 3-1 ｜ 漏出原因 → 改进动作映射

常见漏出原因对应改进动作
测试点不清晰优化用例设计，明确测试点与判定依据。
无用例覆盖分析测试方法，补充边界场景用例。
设备资源缺口提前申请与跟踪测试设备、车辆资源，纳入调度。
执行时间不足提升自动化覆盖率，以并行执行加快验证速度。
偶现问题对开关机、显示异常、卡死等场景做自动化压测。
结果
所负责范围的漏测率保持长期改善趋势，累计降幅 **%。
复盘
指标只有绑定「分类 → 动作 → 复评」才是治理工具；脱离闭环的指标只是报表。
主导角色
个人主导 指标体系与闭环机制；核心参与 数据治理工具为团队共建成果。

案例 CAI 辅助测试设计与质量审计

背景
需求、历史缺陷与法规条款分散，人工检索慢且易漏边界场景；对账与审计类工作高度重复。
约束
模型输出不可全信，质量责任不能外包给 AI；数据处理须在允许边界内进行。
诊断
按任务性质拆分「可委托」与「必须留人」：解析、召回、比对、生成、标记可交给机器；边界确认、修订与准入必须由人完成。
干预
构建机—人双泳道协作（见图 3-4）：机器完成解析、召回、比对、生成与风险标记，低置信度产物自动回退人工；人完成边界确认、修订与「放行 / 补充 / 驳回」的准入决策。

图 3-4 ｜ 机—人协作双泳道

文字等价：机器按序执行 需求解析 → 历史缺陷召回 → 法规条款召回 → 差异比对 → 用例与材料生成 → 风险标记；产物交人工 边界确认 → 修订 → 准入决策；准入决策仅由人做出。

结果
用例设计与审计准备耗时下降 **%，版本准入材料可自动预生成并经人工确认后使用。
复盘
AI 的价值在于把人从检索与比对中解放出来，而不是替代判断；落地效果更多取决于边界设计，而非模型能力本身。
主导角色
团队成果 · 核心参与 测试用例智能生成与质量审计链为团队阶段性共建；个人主导 缺陷处理 SOP 与自动提交流程。

工作原则 · OPERATING PRINCIPLES

  1. 01先定靶心，再谈提效。没有指标方向的优化只是忙碌。
  2. 02让系统承接重复，把人留在判断与责任边界上。自动化替代的是动作，不是责任。
  3. 03经验不沉淀就是损耗。学习、验证、文档、复用，缺一环都不算能力。
  4. 04无人值守的前提是可复位。工程兜底先于效率承诺。
  5. 05AI 负责召回与生成，人负责确认与准入。边界设计比模型能力更关键。
  6. 06可复用才算能力，只用一次只是操作。以「他人能否自助使用」验收技术工作。
